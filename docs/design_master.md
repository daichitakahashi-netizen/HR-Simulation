## 1. プロジェクト概要
本アプリケーションは、100名（および追加10名）の社員データをもとに、複雑な評価重みとペナルティ計算を考慮し、全社売上や特定事業部の利益を最大化する人員配置を算出・比較・決定するための経営・人事向けSaaSである。既存の連番配置のバグを改修し、実務に耐えうる貪欲法ベースの最適化アルゴリズムを導入する。

## 2. アーキテクチャと技術スタック
*   **フロントエンド:** Angular 
*   **UIコンポーネント:** Angular Material (MatSidenav, MatCard, MatTable, MatExpansionPanel, MatDialog, MatChips 等)
*   **状態管理:** RxJS `BehaviorSubject` / Angular Signal を用いた単一ストア (`SimulationStoreService`)
    *   `currentObjective`, `employees` (ロック状態含む), `is110Mode` を一元管理し、変更を検知して自動で最適化エンジンを発火させる。
*   **バックエンド / DB:** Firebase Firestore (※生CSVデータは保存せず、最終決定された「シナリオサマリー」と「理由テキスト」のみ永続化する)
*   **計算エンジン:** ブラウザ側（TypeScript）でのアルゴリズム計算（貪欲法・ヒューリスティック近似計算）

## 3. UI/UX・画面構成（段階的開示とレスポンシブ設計）
全体を「レスポンシブ・サイドナビゲーション」で構成し、以下の画面・ダイアログを提供する。

1.  **① シミュレーション・ダッシュボード (メイン)**
    *   **左カラム:** `MatSelect`による目的選択、`MatSlideToggle`による110名切替、`MatExpansionPanel`による「動的生成された配置理由」の折り畳み表示。
    *   **右カラム（KPI・グラフ）:** 全社KPIサマリー（110名時は緑色`MatChip`で差分表示）。余白を埋める形で「事業部別 売上・利益・人件費のドーナツチャート（ng2-charts等）」を配置。
    *   **右カラム（各事業部）:** A・B・C事業部のステータスカード。各カード下部に「配置メンバー一覧を見る」ボタン（`MatButton`）を設置。
2.  **② 配置メンバー詳細ダイアログ (`MatDialog`)**
    *   事業部カードのボタンから展開。ソート・検索付きの `MatTable` で対象メンバーを一覧表示。
    *   各行に「固定（ロック）」用のトグルを配置（ロック時は行をハイライト）。
    *   ダイアログ下部に「再計算して反映」ボタンを配置し、複数人のロック調整後に一括で再計算を走らせる。
3.  **③ 社員データ・CSV管理画面**
    *   ドラッグ＆ドロップ領域（※ `<input type="file" hidden>` のクリックイベント発火バグを修正済みのもの）。
    *   全社能力の「強み・弱み」統計サマリー。全社員プレビュー機能。
4.  **④ シナリオ比較・意思決定画面**
    *   保存された複数の配置案を横並びのカードで比較し、「決定」ボタンでFirestoreへサマリーのみ保存。
5.  **⑤ 配置方針・レポート出力画面**
    *   A4一枚に最適化されたエグゼクティブ・サマリー。全社売上58億円未達時は赤色警告バッジを表示。

## 4. 計算エンジンの追加・改修仕様
要件定義書の数式に基づき、以下の実務ロジックを実装する。
*   **最適化アルゴリズム（貪欲法）:** 
    1. 各社員の事業部ごとの貢献度スコアを算出。
    2. 絶対条件である「最低配置人数（A:30名, B:20名, C:10名）」を満たすようスコア上位者を最優先で確保。
    3. 残りのメンバーを、ドロップダウンで選択された目的（限界売上・限界利益が高い事業部）に応じて優先的に分配。
*   **動的テキスト生成ロジック:** 
    固定文言を廃止し、「選択された目的」「最大の貢献要素（一番伸びた事業部と起因スキル）」「回避したペナルティ（例：A事業部の人員不足ペナルティ）」「最終結果（全社売上・コスト）」を変数として組み合わせ、説得力のある3〜4文の理由テキストを自動生成する。
*   **適正人数の動的スケーリング:** 
    110名モード時、充足率計算の分母を `基準適正人数 * (全社員数 / 100)` で動的に拡張する。

    *   目的変更イベントに連動した最適化アルゴリズム（貪欲法・制約条件クリア）の繋ぎ込み。
    *   配置理由の動的テキスト生成ロジックの実装。
    *   CSVアップロードボタンのHTML/イベントバインディングバグ修正。
*   **Phase 2: 見た目の治療（ダッシュボードUIの完成）**

*   **Phase 3: 手動調整UIの実装（ダイアログ＆ロック）**
    *   「配置メンバー一覧を見る」ボタンと `MatDialog` コンポーネントの作成。

*   **Phase 4: 出力・最終調整**
